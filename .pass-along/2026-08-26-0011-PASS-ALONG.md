## Decisions and rules

- **A failed tool install terminates the box; nothing else does** (ADR-0010). The predicate is
  `terminatesInstance()` in `bootstrap/failure.ts`: `phase === 'tool' && policy === 'terminate'`.
  No config makes a repo failure terminate.
- **Instance released before the row is failed** — the provisioning-timeout order — so a crash
  between the two leaves a retryable row, never a failed row beside a billing machine.
- **`failed` leaves only through `terminate`.** `lifecycle.sync` records provider state on a
  failed row but never promotes it to `terminated`; `terminated` rows are hidden from the
  dashboard and would hide the explanation. `failed-billing.test.ts` was changed to expect this.
- **Repo clones are `optional: true` plan steps.** Setup scripts must guard for an absent repo
  dir (documented in writing-a-pack).
- **The report lives on the row, not on the SSE event** — whole logs do not belong on a
  broadcast. A terminal `server-status` is the SPA's cue to `getServer()`.
- **Warnings merge by step id in callback mode, replace whole in push mode**
  (`recordWarnings` `mode`). `failBootstrap` keeps warnings already on the row minus the step
  that then failed for real.
- **Mirror fallback: no apt retries.** Measured on noble's apt 2.8.3: a 503 gets ONE request;
  `Acquire::Retries` covers connection failures only and already defaults to 3 with backoff
  (7 s). Raising it delays the fallback minutes per step. Written into the memory file so nobody
  re-adds retries.
- **Agent fan-out was not used this session** — the two PRs were tightly coupled across
  core/web/docs and built by the orchestrator directly.
