## Decisions and rules

- **Region fix refuses; it does not auto-create a second pair.** `assertSameRegion()` throws
  `invalid_spec` naming both regions and both remedies. Auto-creating a region-suffixed vnet/NSG
  would change resource naming and needs a migration story. Recorded in `e7b8f4b`.
- **`ensureNetwork()` is deliberately not memoized.** Two GETs per create against a
  minutes-long operation. The memo hid three bugs. Do not put it back.
- **The test fake now stamps subnet ids and reflects child subnet PUTs onto the parent**, as
  real ARM does. The old fake could not adopt a subnet, so the shared-network test was
  measuring the memo, not adoption. Any future "adopts on the next provision" assertion has to
  hold *without* a cache.
- **Quota is not read, on purpose, until the owner says otherwise** (#116).
- **`rockysurf-1nfc` was overclaimed and corrected.** The bug was already fixed on main by
  `rockysurf-gg9x`; the session diagnosed it against a checkout that predated gg9x. What
  shipped is a narrower refinement — a *deliberately* disabled provider's rows should not carry
  `syncError`. The commit, comment and tests say that; the bead carries a correction note.
  Lesson generalized in #115.
- **Every finding from the run belongs in the public tracker, not only in beads.** Beads are
  laptop-only; #116 exists because `xmk0` was invisible to anyone but this machine.

## Traps

- **This machine has eleven worktrees and the session opened in an archived one.**
  `~/code/1-open-source-rocky-surf-v0-1` builds, tests green, and shares **no history** with
  the public repo (462 commits, empty merge-base). Its files were also *behind* main. Check
  `git merge-base HEAD origin/main` before the first edit. Move work by `git diff | git apply
  -3` onto a branch from `origin/main`, never by copying files — the stale versions revert
  other people's work. Full write-up in #115.
- **`git apply -3` stages everything it applies.** A following `git add <three files>; git
  commit` swept all nine files into one commit. Use `git commit --only <paths>`. Caught before
  push; the five commits were redone.
- **The `dcg` guard blocks `git restore`, `git reset --hard` and `git checkout -- <path>`** for
  agents, every time, with "have the user run it manually". Plan around it; do not retry.
- **Azure SKU restrictions lie before `Microsoft.Compute` is registered.** Pre-registration,
  eastus showed 0/12 catalogue sizes orderable; post-registration, 6/12. The provider's
  `isAvailable()` is correct; the input was not. Register both namespaces first (now step 0 in
  `azure.md`).
- **SKU availability ≠ core quota.** A size can show no restriction and still fail at the VM
  PUT with `OperationNotAllowed … Current Limit: 0`. Two gates; the catalogue reads one (#116).
- **`az vm list-usage` is not a reliable quota signal.** It reported limit 0 for westus2 while
  two creates succeeded there. Trust what `create` returns.
- **`createRatePerHour` (default 4) counts failed creates.** The run hit it mid-way; a failed
  `MissingSubscriptionRegistration` attempt had used a slot. Raise it in config for an exit
  run, put it back after.
- **The CLI's `--size` takes a tier (`small|medium|large`), not a SKU**, and the CLI cannot
  pick an architecture. `small` on Azure resolved to `Standard_B2ls_v2` (amd64). The API takes
  `arch` and `offeringId` directly; use `POST /api/v1/servers` for an arm64 leg.
- **`rockysurf token` must come before `--config`.** `rockysurf --config x token` → `unknown
  option: token`, then prints server help that does not mention `token`. Noted on #112.
- **`--help` documents only the server.** `token`, `list`, `create`, `stop`, `ssh`,
  `ssh-config` are discoverable only from source or error hints. On #112.
- **A non-interactive SSH has a minimal PATH** — `~/.local/bin` is absent, so `claude`, `bd`,
  `bv`, `agent-deck` look MISSING. `bash -lc` finds them. Not a pack bug.
- **`with-key` is the owner's personal keychain helper**, defined in their `~/.zshrc`. It is
  how the SP secret reached the control plane without ever entering the transcript
  (`with-key AZURE_ROCKY_SURF_SP_PASSWORD bash -c '…'`). It is not a Rocky Surf thing and
  does not belong in any doc. The owner was explicit about this.
- **Exports from the owner's `!` prompt do not reach agent shells.** Each Bash call starts
  fresh from the profile. Inject per command.
- **macOS: no `timeout`, no `stat -f` inside a clobbered-PATH subshell.** Set `PATH`
  explicitly at the top of scripts that build their own environment.
- **The owner's `~/.rockysurf/` is live data.** 31 server rows, one not terminated. An exit run
  must set `server.dataDir` elsewhere. It did.
- **Azure auto-creates `NetworkWatcherRG`** the first time you make networking in a region.
  Free, platform-owned, and the SP *could not* have created it — incidental proof the role
  boundary held. Not ours to delete without asking.
