## Decisions and rules

- **UI verification bar (hard rule, learned twice)**: no UI-touching change is "verified"
  without the Playwright suite or a real logged-in browser click-through. Component tests,
  wiring tests, and real-HTTP checks all passed while the page was unusable — twice in one day
  (#303's dead section, #311's wedged Add). Codified in AGENTS.md via #314.
- **PR admin comments are for the owner-as-merger** (memory updated in #316): "what you must
  do" is binary; no optional setup commands; no internal tooling rules; future actions become
  issues, never comment paragraphs.
- **Plan → adversarial review → build** worked well for the two design-heavy issues (#289,
  #304): both debates killed a wrong design before code (harness flag; socket-peer detection)
  and caught two would-be data-loss bugs (#295's upsert sentinels) and one would-be lockout
  (#304's first-sync adopt-not-revoke). Worth the cost for cross-cutting issues; skip for
  well-specced small ones.
- **Fork provenance never travels**: `derivedFromPackId` and fork-inherited root-relative
  artwork are stripped from exports — a text file can't carry a trustworthy ∆ (ADR-0020).
- **`alwaysInstall` is installation state, not file content** — editable on file-backed tools,
  never a member of the tool-file format, unioned after the resolvePack branch.
- **Provision stays additive on AWS forever**; only an explicit confirmed sync may revoke
  (#309's contract; test pins provision-never-revokes).
- Migration numbers and ADR numbers collide across parallel agents — verify what's free at
  rebase time (0018/0019/0020/0021 all claimed by different PRs today).

## Traps

- **A worktree can be pruned out from under a running agent** — the #304 agent's shell
  silently landed in the owner's live checkout mid-session. It caught it and made a fresh
  worktree; nothing was run in the live tree. Agents should re-verify `pwd`/`git worktree list`
  after any long gap.
- **Never close/reopen a PR to nudge a stale head after a force-push** — GitHub refuses the
  reopen once the old head is unreachable (#298 was briefly closed this way). Waiting works;
  the head syncs itself in minutes.
- **`pnpm --filter rockysurf` matches the workspace root too** — one shard silently re-ran the
  entire suite. Shards run in their package directory now; a self-test forbids `--filter`.
- **A `test.fail()` reproduction goes red the moment the bug is fixed** ("Expected to fail,
  but passed") — plan the one-line flip into the merge order, on both PRs, with a named owner.
  It worked cleanly today (#311→#314→#317) but only because both agents wrote it down.
- **Shared-scratchpad filenames collide across agents** — two agents fought over `run.sh`;
  helper files need agent-unique names (now in the brief).
- **The SettingsPage flake (#313)** fires under CPU load and on schedule pressure; a red
  `Test` on an untouched tree is probably it — rerun before diagnosing.
