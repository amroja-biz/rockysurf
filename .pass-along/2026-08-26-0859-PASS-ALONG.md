## Decisions and rules

- **A failed row core released stays released.** In `syncObserved`, `status === 'failed' &&
  providerState === 'terminated'` ignores any provider read that says otherwise. `failed` leaves
  only through `terminate`, so a machine reported present after core released it is the
  provider reporting the past. Narrow on purpose: a kept machine (non-tool failure) still syncs
  and still bills, and a test pins that.
- **A terminal `server-status` frame is a cue to re-read the row**, not a patch. The report and
  the billing verdict live on the row (ADR-0010); the SPA now calls `getServer()` on
  `failed`/`terminated`. The dashboard still patches status only — it renders no billing detail
  from the frame, so it was left alone.
- **Unreadable quota is not "no quota".** `coreQuota()` returns null on any failure; `available`
  then reflects the SKU gate alone. Never mark a size unavailable on the strength of a read
  that failed. 403 is cached 60 s and warned once per process; other failures 30 s.
- **Family join is case-insensitive.** `skus` says `StandardDalsv7Family`, `usages` says
  `standardBpsv2Family`. The regional `cores` row is a gate too.
- **`Offering.unavailableReason` is additive and only beside `available: false`** — the
  conformance suite rejects it on an available offering.
- **A quota refusal is not "sold out."** Every surface that said "sold out right now" now
  prefers the provider's reason; the tier resolvers lead with it only when every matching
  candidate gives the same one.
- **Throwaway packs never go in `packs/`.** CI smokes everything there. Import them.
- **Work in a fresh worktree when the owner's core runs from the main checkout** — `pnpm -r
  build` in `~/code/rockysurf` would replace the SPA their browser is loading. Build in the
  worktree (`pnpm install --frozen-lockfile && pnpm -r build`; a fresh worktree has no `dist`).
- **Beads are done.** The DB is empty and purged; file GitHub issues. `bd` still only works from
  `~/code/rockysurf-open`.

## Traps

- **`provider_state_at` later than the failure timestamp is the tell** for the sync-overwrite
  class of bug. Azure's `describe()` answers `Succeeded`/running for minutes after a DELETE is
  accepted; EC2 answers `shutting-down`. Any code that trusts the first describe after a
  terminate is wrong.
- **The web wiring tests have no jest-dom** — `toBeInTheDocument` throws "Invalid Chai
  property". Use `toBeTruthy()` on `getByRole`.
- **A fresh worktree has no `dist`**, and core's tests import `@rockysurf/provider-sdk` by
  package entry: "Failed to resolve entry for package" means build first, not a broken import.
- **`packages/rockysurf` has no vitest binary** — `pnpm --filter rockysurf exec vitest` fails
  with "Command vitest not found"; its tests run through the root `pnpm run check`.
- **The CLI's offering type lives in `packages/rockysurf/src/mcp/tools.ts`**, not in
  `cli/commands.ts` — a new `Offering` field has to be added there too or typecheck fails on
  the CLI.
- **zsh aliases `c`** — defining a shell function named `c` in a Bash tool call fails with
  "defining function based on alias".
- **`bd close` refuses an epic with open children and a bead blocked by an open dependency**
  — `--force` per id; the launch epic needed it.
- **`bd gc` decay deletes closed beads older than 90 days** — 304 went in one go. That was the
  intent, but it is not undoable.
- **`az vm list-usage` was distrusted for a whole session on one observation** that was almost
  certainly a family mismatch. Trust the endpoint; verify the family name.
- Carried, still true: node 24 (`nvm use 24` per shell); `gh pr checks --watch` exits 0 on
  failure; BSD sed has no `t` label; dcg guard blocks `rm -rf`/`git restore` for agents; apt
  gives a 503 exactly one request.
