## Decisions and rules

- **Personal vs official providers is a VERIFICATION boundary, not only an install mechanism.**
  Official = composed into `packages/rockysurf/src/compose.ts`; gets a nightly real-cloud leg.
  Personal = installed under `<dataDir>/providers`; its author and installer verify it; its
  capability column ships fully daggered (the `byo` model). DigitalOcean is personal. ADR-0026
  amendment 2026-09-05; the skill and writing-a-provider.md say it.
- **Shop rulings**: providers are a tab on the one "Shop" page (owner calls it "the shop"); the
  trust sentence is Rocky Surf's constant rendered by the client, never a registry field (ADR-0006);
  the installer never runs npm, so a shop provider tarball is self-contained (zero runtime deps).
- **Small changes → only relevant checks** (#389). Keep-both conflict resolutions and
  core/SDK/multi-package changes still get the full gate.
- **Stacked PRs vs squash-merge**: after the base PR squash-merges, the stacked branch must be
  rebased `--onto origin/main <base PR's headRefOid>` (patch-ids differ; `git cherry` won't show
  them as duplicates). And **merging the base with `--delete-branch` CLOSES the stacked PR** —
  GitHub will not reopen it onto a deleted base; open a fresh PR (#381 → #390). Retarget stacked
  PRs to main BEFORE merging their base, or don't delete the branch.
- **DO facts now written**: the API reference documents `user_data` ≤ 64 KiB plain text
  (`userDataMaxBytes: 65_536` is a transcription, daggered); tokens are team-scoped with no OIDC
  and no minting API.
