## Decisions and rules

- **Absent beats present-at-zero** (#143): a price meter at 0 is excluded and logged; the feed
  run fails rather than publish a document the shipped reader rejects.
- **Setup scripts inherit the clone step's git credentials via env**, never argv or on-disk
  config (#144).
- **`agent.sh` establishes `HOME`/`USER`/`LOGNAME` itself**; the smoke harness must start the
  agent with them unset so it matches `systemd-run` (#162, `docs/bootstrap-contract.md`).
- **A released failed row costs zero provider calls on list** (#164, ADR-0010 d.5). The #138
  post-describe guard is folded into that early return.
- **One Terminate/Dismiss rule** — `lib/serverActions.ts`; card and detail page both read it (#155).
- **`preferences` is the only config block re-read live** (#152); `registry.sources` applies at
  restart (#159). Both stated in `docs/self-hosting.md`.
- **A `.yaml` URL is a pack** — presented as a one-entry index so browse/install/provenance share
  code (#159). https-only, admin-only, `trust: unverified`, never fetched at boot or on save.
- **Nightly GCP uses two SAs** — lifecycle under the published role, sweep under a CI-only role,
  because the published role deliberately lacks `compute.disks.list` (#150).
- **Orchestration pattern that worked**: shared brief file in the scratchpad + `isolation:
  worktree` + per-issue model choice + agents told "don't wait on CI during an outage, report it
  queued". Bundle issues that touch the same component (cards: #113/#128/#121) into one agent;
  sequence dependent ones (#124 after #122, branched from its PR then retargeted).

## Traps

- **During a GitHub webhook outage, do NOT push new SHAs to re-trigger CI.** It orphans the runs
  you already have (the PR's checks tab keys on head SHA) and the new push gets no run either. I
  did this with empty commits on three branches and had to rewind them. What worked: wait, then
  `gh run rerun <id>` for killed runs and close/reopen for PRs with no run — but close/reopen
  took ~5 minutes to produce a run even after recovery.
- **"The job was not acquired by Runner of type hosted even after multiple attempts"** with zero
  steps run = GitHub, not you. Check `githubstatus.com/api/v2/components.json`.
- **`gh pr checks --watch` exits 0 on failure** and a queued/cancelled run makes the PR show
  `UNSTABLE`/`UNKNOWN`; `mergeStateStatus` flips to `UNKNOWN` for ~10 s after every merge to main.
- **Agent-tool worktrees are locked** (`.claude/worktrees/agent-*`); `git worktree remove -f -f`
  after confirming pushed + clean. A no-change agent's worktree auto-removes.
- **Background agents "finish" when they stop their turn to wait on a Docker run or a monitor**
  — the notification is not completion. Nudge with "don't end your turn while X is running".
- **Agents that arm per-check CI monitors wake the orchestrator per check.** Tell them to report
  once when the whole set is done, or take the CI watch centrally.
- **`az iam roles update --file` without etag prompts "Replace existing role (Y/n)?"** — it's the
  generic no-etag warning; diff `includedPermissions` first (`gcloud iam roles describe`) and it's
  a no-op if identical.
- **ports.ubuntu.com arm64 404s on a specific package version** = archive index ahead of pool;
  re-run later, don't patch packs.
- Carried, still true: node 24 (`nvm use 24`); web wiring tests have no jest-dom; fresh worktree
  has no `dist`; `packages/rockysurf` has no vitest binary; BSD sed; zsh aliases `c`.
