## Traps

- **The merge race**: an owner who merges fast can merge a PR seconds before your push
  registers — `git push` success + local `gh pr view` showing the old commit count is the
  smell. After pushing to an open PR, confirm `headRefOid` moved before reporting the push as
  part of the PR.
- **gitleaks scans every branch** (CI checks out `fetch-depth: 0`), so a `secret:X_API_KEY=…`
  placeholder committed on ANY branch fails the Secret scan on EVERY open PR. Cost two CI
  churns today. Reword placeholders; `gitleaks dir .` locally only checks the tree, not
  history.
- **`gh pr view --json commits` can lag a just-pushed commit**; `mergeStateStatus` sits
  UNKNOWN for ~10s after any main movement (known, still true).
- Carried and still true: node 24 via `~/.nvm/versions/node/v24.19.0/bin` (default shell is
  node 20); `/usr/bin/grep` for CI parity; foreground `sleep` blocked in this harness; the
