## Decisions and rules

- **MCP architecture is settled and spec-verified** (#348 closing comments): the MCP server is
  a thin translation layer over core's HTTP API; "self-contained" in the MCP spec modifies
  requests, not servers; never embed core in the MCP process (duplication + second writer on
  one dataDir + master key in an agent-facing process). Retire the phrase "the MCP is a client
  of the web server" — say "translation layer in front of the control plane's HTTP API."
- **Absence must explain itself** — the session's recurring theme, now mechanized twice:
  #355 (scope notes on tools referencing withheld tools, property-tested) and #352 (startup
  preflight). Apply it to future "X is missing" reports before assuming a registration bug.
- **Provider model** (#294): official providers ship in-repo; personal providers are full-trust
  installed software (Option A — no sandbox, one honest sentence); the shop is committed;
  anything core COMPUTES with must be a typed capability, never advisory text; config shape
  should come from provider-declared schema. An answer that fits no existing capability →
  stop and file the ADR, never approximate.
- **provider-sdk may carry pure runtime code** (ADR-0024, #356) — its charter is zero
  dependencies, not zero code. The zero-import assertion now covers every source file.
- **Config schema drift is the nightly-killer class** (#343): core's strictObject and a
  provider package's own schema describe the same section; #346's parity test is the guard —
  extend it when adding provider config keys.
- **us-east-1e sells almost no modern instance types**; any AWS code choosing a subnet/AZ must
  be type-aware (#358). `DescribeInstanceTypeOfferings` is now in the published role.
- **Do not remove an agent's worktree until its issue is fully settled** — removal breaks
  SendMessage resumability (learned when the owner sent #348 back to the jury room and the
  agent could not be resumed; the debate survived only because the friend held the context).
