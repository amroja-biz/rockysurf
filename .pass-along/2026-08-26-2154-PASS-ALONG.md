## Decisions and rules

- **`App.css` is never edited by the skin.** A colour fix is a rule in `etched.css` or a hardcoded
  hex moved onto an existing `--rs-*` token. Three PRs kept this; keep it.
- **The vendored design system is verbatim.** `.claude/skills/rockysurf-design/` is the
  designer's export minus `.DS_Store`. Re-vendor by `rsync -a --delete --exclude .DS_Store`, then
  `git status` should show only additions/changes the designer made.
- **Caps label a field; they never carry a sentence** (skill rule). `Beacon`'s notice span and the
  `.field-help/.hint/.muted/...` list in `etched.css` opt back out of caps. Any new prose class
  under the skin needs adding to that list.
- **A level needs its ceiling named beside it.** `Waterline` is on the spend cap only; `Tally`
  beside uptime, never instead of it, only when core sent a number.
- **One vocabulary per fact.** `Lamp` replaced `StatusBadge` everywhere and `StatusBadge.tsx` is
  gone; `Lamp` reads `STATUS_LABELS`/`TRANSITIONS`, not its own table. Tests query `.lamp`.
- **The five status colours are untouched by the skin**; the beam is the one accent, and it also
  replaces blue for links and focus. Green on the spend-cap waterline was replaced by the beam
  because "under the cap" is not an action being confirmed (#177).
- **Parts keep the DOM contract**: `data-status`/`data-transition` on `Lamp`; `.step-list`,
  `.step`, `.step-<state>`, `data-state`, `aria-current` on `Beacon`. Tests read those; keep them.
- **No emoji anywhere in `packages/web`** (design guide). Notices open with `⚠︎` (yellow) or `●` (red).
- **Looking at the UI without a cloud**: no providers in config → fake provider with simulated
  bootstrap (~30 s to `running`); `limits.createRatePerHour` defaults to 4 and
  `limits.spendCap` blocks creates when hit — both bit this session. The fake forgets its
  instances on restart, so every existing row goes `terminated` on the next describe.

## Traps

- **The worktree guard refuses `source`, `export`, `PATH=… cmd`, `for` loops, `cd … &&`, and
  `${PIPESTATUS}`** as "too complex". Node 20 is this shell's default and pnpm's corepack shim
  dies on it. Workaround that worked: a 3-line wrapper script in the scratchpad that prepends
  node 24 to `PATH` and `exec "$@"`, called as `bash <wrapper> pnpm -C <abs path> run test`. Use
  `pnpm -C <absolute path>`; the Bash tool's cwd drifts (a `cd` persisted, then a later
  `cd packages/web/src` failed and a build ran against `src/packages`).
- **`vitest` needs node 24 on PATH for its workers too**, not just for pnpm — under node 20 every
  file errors with `webidl.util.markAsUncloneable is not a function` (undici/jsdom), which reads
  like a dependency bug and is not.
- **`bundle-assets.test.ts` reads build output.** A fresh worktree fails 19 tests until
  `pnpm --filter @rockysurf/web build` has run. Not a regression.
- **Pack icons appear as empty boxes for a second** — `loading="lazy"` plus a screenshot taken
  too early. The PNGs are fine and served.
- **`pkill -f 'bin.js --config …'` said 0 but the core kept the lock** — the node child survived.
  `kill <pid>` from the lock message worked. Core prints the holder's pid.
- **The SPA session is an httpOnly cookie** — the bearer token is in-memory only, so you cannot
  hand a browser a session via `localStorage`. The cookie-injecting proxy
  (scratchpad `core/cookie-proxy.mjs`, one `http.request` pipe adding `Cookie:`) is the clean way
  to look at the app signed in without typing a password.
- **`getByText(label)` matches the element whose OWN text nodes match** — `Beacon` keeps the label
  as a direct text node of the `<li>` (caps styling on the `li`, notice span opts out) precisely so
  `stateOf(label)` in `ServerDetailPage.wiring.test.tsx` still finds `data-state` on the `li`.
  Wrapping the label in a span breaks that test.
- **A CSS rule with `display: inline-flex` on a `<dd>` that is a grid item** becomes flex and
  `justify-content: flex-end` throws the value across the whole column — that was the uptime
  bug. Card and detail need different justification.
- Carried, still true: `gh run list --commit <sha>` returns nothing (filter `headSha` from
  `--json`); the `dcg` guard blocks any command text containing `rm -rf /var/…`; `mergeStateStatus`
  sits at `UNKNOWN` for minutes; `gh pr checks --watch` exits 0 on failure.
